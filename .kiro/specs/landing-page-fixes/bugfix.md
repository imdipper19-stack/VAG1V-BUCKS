# Документ требований к исправлению багов

## Введение

На лендинге (`frontend/src/app/page.tsx`) обнаружены два бага:

1. **Секция «Последние успешные выдачи»** отображает захардкоженные данные из массива `LIVE_ORDERS` вместо реальных завершённых заказов из API.
2. **Секция «Пакеты для быстрой покупки»** исчезает при клике на карточку пакета из-за некорректного взаимодействия IntersectionObserver и React-ререндера.

Оба бага влияют на доверие пользователей: первый показывает фейковые данные, второй ломает основной flow покупки.

## Анализ багов

### Баг 1: Захардкоженные данные в секции «Последние успешные выдачи»

#### Текущее поведение (Дефект)

1.1 КОГДА пользователь открывает лендинг ТОГДА секция «Последние успешные выдачи» отображает статичный массив `LIVE_ORDERS` с фейковыми данными (`#VB-2418`, `2 400 V-Bucks`, `7 минут`, `Выдано`)

1.2 КОГДА в системе появляются новые завершённые заказы ТОГДА секция «Последние успешные выдачи» не обновляется и продолжает показывать те же захардкоженные данные

#### Ожидаемое поведение (Корректное)

2.1 КОГДА пользователь открывает лендинг ТОГДА система ДОЛЖНА запросить реальные завершённые заказы через `ordersApi.list({ status: 'completed', limit: 4 })` и отобразить их в секции «Последние успешные выдачи» (orderId, количество V-Bucks, время с момента завершения, статус)

2.2 КОГДА запрос к API завершается ошибкой ТОГДА система ДОЛЖНА отобразить fallback-данные из массива `LIVE_ORDERS` без отображения ошибки пользователю

2.3 КОГДА API возвращает пустой список завершённых заказов ТОГДА система ДОЛЖНА отобразить fallback-данные из массива `LIVE_ORDERS`

#### Неизменное поведение (Предотвращение регрессий)

3.1 КОГДА пользователь открывает лендинг ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ загружать пакеты из `pricingApi.list()` независимо от загрузки заказов

3.2 КОГДА секция «Последние успешные выдачи» загружает данные ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ отображать остальные секции лендинга без задержки (не блокировать рендер)

3.3 КОГДА API заказов недоступен ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ корректно отображать весь лендинг с fallback-данными

---

### Баг 2: Исчезновение секции пакетов при клике

#### Текущее поведение (Дефект)

1.3 КОГДА пользователь кликает на карточку пакета в секции «Пакеты для быстрой покупки» ТОГДА вся секция исчезает (становится невидимой) из-за потери CSS-класса `is-visible` после React-ререндера

1.4 КОГДА React выполняет ререндер карточек пакетов (при изменении `selectedPackage`) ТОГДА новые DOM-элементы получают класс `landing-reveal` без класса `is-visible`, а IntersectionObserver уже не наблюдает за ними (вызвал `unobserve` после первого пересечения)

#### Ожидаемое поведение (Корректное)

2.4 КОГДА пользователь кликает на карточку пакета ТОГДА система ДОЛЖНА выделить выбранный пакет (добавить класс `featured`) без исчезновения секции

2.5 КОГДА React выполняет ререндер элементов с классом `landing-reveal` ТОГДА система ДОЛЖНА сохранять видимость элементов, которые уже были показаны анимацией

#### Неизменное поведение (Предотвращение регрессий)

3.4 КОГДА пользователь прокручивает страницу к секции впервые ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ анимировать появление элементов через IntersectionObserver (scroll-reveal эффект)

3.5 КОГДА пользователь выбирает пакет и нажимает «Перейти к оплате» ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ корректно перенаправлять на страницу оплаты с выбранным пакетом

3.6 КОГДА пользователь выбирает другой пакет ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ обновлять панель «К покупке выбран пакет» с актуальной информацией

## Условие бага (Bug Condition)

### Баг 1: Захардкоженные данные

```pascal
FUNCTION isBugCondition_LiveOrders(X)
  INPUT: X типа LandingPageLoad
  OUTPUT: boolean
  
  // Баг проявляется всегда — данные никогда не загружаются из API
  RETURN TRUE
END FUNCTION
```

```pascal
// Свойство: Fix Checking — Загрузка реальных заказов
FOR ALL X WHERE isBugCondition_LiveOrders(X) DO
  result ← renderLiveOrdersSection'(X)
  ASSERT result.dataSource = "API" OR (result.apiError = TRUE AND result.dataSource = "fallback")
END FOR
```

```pascal
// Свойство: Preservation Checking — Остальной лендинг не затронут
FOR ALL X WHERE NOT isBugCondition_LiveOrders(X) DO
  ASSERT F(X) = F'(X)
END FOR
```

### Баг 2: Исчезновение секции пакетов

```pascal
FUNCTION isBugCondition_PackageDisappear(X)
  INPUT: X типа UserInteraction
  OUTPUT: boolean
  
  // Баг проявляется когда пользователь кликает на пакет (вызывает setSelectedPackage)
  RETURN X.action = "clickPackageCard" AND X.sectionAlreadyVisible = TRUE
END FUNCTION
```

```pascal
// Свойство: Fix Checking — Секция остаётся видимой после клика
FOR ALL X WHERE isBugCondition_PackageDisappear(X) DO
  result ← handlePackageClick'(X)
  ASSERT result.sectionVisible = TRUE AND result.selectedPackageHighlighted = TRUE
END FOR
```

```pascal
// Свойство: Preservation Checking — Scroll-reveal анимация работает
FOR ALL X WHERE NOT isBugCondition_PackageDisappear(X) DO
  ASSERT F(X) = F'(X)
END FOR
```
